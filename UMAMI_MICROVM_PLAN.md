# Umami microVM with isolated public collection

## Context

Run Umami in a NixOS microVM on patroclus for the Astro site `/Users/alexander.jackson/code/gracebobber`. Expose only tracking at `analytics-grace.ajax.lol`, with the authenticated dashboard at `analytics.grace.ajax.casa` restricted to `172.22.0.0/16` and Tailscale. Retain host-enforced isolation and automatically block IPs with bad reputations using HAProxy and CrowdSec's supported SPOA bouncer. User selected **reputation blocking only**: no collector-log acquisition, attack-signal sharing or paid subscription. The flat public hostname fits standard Cloudflare TLS. This is an execution plan, not an implemented or runtime-verified deployment.

The reference is [Solène's infrastructure article, §5.2](https://dataswamp.org/~solene/2026-10-15-selfhosting-infrastructure-incus-os.html#_Incoming_public_traffic): CrowdSec consumes application attack signals and community blocklists; its nftables bouncer blocks real source IPs before a TCP-only HAProxy. Keep CrowdSec and HAProxy, but adapt enforcement to Cloudflare Tunnel: the kernel sees the tunnel transport, so the HTTP integration must check the verified visitor IP instead. Do not substitute rate limiting or a manual denylist for reputation blocking.

### 4. Keep HAProxy as the public-only proxy

Enable native `services.haproxy` in the guest. The locked package is **3.3.11**, with PCRE2; keep the module's `haproxy -c` startup/reload validation and systemd hardening. Configure one HTTP frontend at `.2:8080`, one application backend at `127.0.0.1:3000`, and one TCP SPOA backend at `.1:9000`. No TLS, dashboard routing, Lua, custom bouncer, unsupported `internal.*` fetches or second HTTP proxy.

Apply native HAProxy rules in this order:

1. Reject non-gateway connections with `tcp-request connection reject` before any HTTP processing. The host UID firewall remains the real authority. Do not re-check mutable `src` as the transport peer after `set-src` or on later keep-alive requests.
2. Require exactly one Host equal to `analytics-grace.ajax.lol`. Require exactly one full `CF-Connecting-IP` header, no comma/list/whitespace/brackets/zone suffix, and a successful native `req.hdr_ip` parse. A character allowlist `^[0-9A-Fa-f:.]+$` is supplemented by rejecting IPv4-with-port form `^[0-9.]+:[0-9]+$`. Empty, duplicate, list and invalid values return 400. Only then `http-request set-src req.hdr_ip(cf-connecting-ip)`. Never fall back to XFF, X-Real-IP, True-Client-IP or the gateway. Repeat validation for **every** request on a reused tunnel connection.
3. Permit only exact raw request-target `/script.js` with GET/HEAD, or exact `/api/send` with POST/OPTIONS (`url -m str`, not prefix matching or normalization). Other targets/methods return 404. Ingestion also requires exactly one Origin equal to `https://gracebobber.com` or `https://www.gracebobber.com`, otherwise 403. Script requests need no Origin. Query suffixes, encoded paths, trailing slashes and absolute-form targets are not public routes.
4. Apply native CIDR ACLs generated from `blockedCidrs`, returning 403; omit the ACL/rule for an empty list. Invalid CIDRs must fail config validation. Use one `stick-table type ipv6 size 100k expire 1m store http_req_rate(10s)`, tracking the verified `src` per request and returning 429 when its rate exceeds 100 requests per 10 seconds. This is an initial native sliding-rate threshold, not a promise of NGINX's token-bucket burst semantics. Do not aggregate all visitors under the tunnel gateway.
5. Ask CrowdSec for this verified visitor IP, using the native SPOE group described below. Ban/captcha/challenge decisions return plain 403; missing/unknown verdict or SPOE transport error returns 503. Only explicit `allow` reaches the application. No interactive challenge, cookie, AppSec body inspection, redirect or third-party request from a visitor's browser.
6. Reject any Transfer-Encoding with 411 and any Content-Encoding with 415. POST requires a single parser-valid Content-Length, otherwise 411; declared size above 65536 returns 413. Non-POST public routes must have no body. Store the POST's native advertised length in `txn.expected_length`; run `http-request wait-for-body time 10s`, then require `req.body_len,sub(txn.expected_length) -m int eq 0`, otherwise reject 400. This comparison is valid **only because chunked bodies are already forbidden and the fixed advertised length has been capped**. It prevents an early EOF or full buffer from being mistaken for a complete body. HAProxy's parser handles malformed/conflicting framing; do not write a protocol parser.
7. Strip all inbound headers except Host, User-Agent, Content-Type, Content-Length, Origin, Access-Control-Request-Method, Access-Control-Request-Headers, x-umami-website-id, x-umami-hostname and x-umami-cache, using native case-insensitive `del-header -m reg` with an anchored negative-lookahead allowlist. Set Host to the public name, X-Real-IP/X-Forwarded-For to verified `src`, and X-Forwarded-Proto to `https`. Never forward client credentials, middleware override headers, CF location headers or Transfer-Encoding. Hide response Set-Cookie; disable proxy caching.

Use `tune.bufsize 131072`, `maxconn 256`, `timeout connect 2s`, `timeout http-request 10s`, `timeout client 10s` and `timeout server 15s`. Reject request headers above 16 KiB using native `req.hdrs,length` before waiting for a body; retain the native header-count limit. The larger buffer accommodates the allowed fixed-length body, while the explicit length comparison rejects incomplete input rather than trusting buffer fullness. Verify these exact expressions with the pinned binary and size/EOF tests; never replace them with undocumented internals to make a test pass.

[HAProxy's documented wait semantics](https://github.com/haproxy/haproxy/issues/2410) stop on completion **or buffer fullness**, and return 408 on the wait deadline. The fixed-length policy is the deliberate tradeoff versus NGINX's simpler native cap on both fixed-length and chunked bodies. Umami's tracker uses a known-length JSON fetch body; nevertheless, a real browser→Cloudflare Tunnel→HAProxy POST preserving Content-Length is a publication gate. If that fails, revisit the framing policy rather than silently opening chunked ingestion or moving the public proxy onto the host.

Forward OPTIONS/POST to Umami. [Umami 3.2.0's native headers](https://github.com/umami-software/umami/blob/v3.2.0/next.config.ts) provide wildcard allow-origin/allow-headers without allow-credentials; Next supplies OPTIONS 204. Keep the tracker's default `credentials: omit`. Origin filtering limits browser misuse; exact method/target gates—not CORS—protect private APIs. Log only verified client IP, method, permitted route, status, timing and reputation error/verdict through stdout to the bounded guest journal; never bodies, query strings, cookies or tokens.

## Assumptions & contingencies

- Public collection is anonymous: Origin gates and domain restrictions reduce accidental misuse, not forged analytics. This design trusts Cloudflare, the host proxies/reputation service and the hypervisor. It blocks public admin routes and lateral guest connections except the explicit IP-decision endpoint, but cannot protect the analytics database or served JavaScript from a compromised guest. SPOA is an additional host parser exposed to that guest, not a general network escape.
- Reputation-only CrowdSec Lite is selected: no collector-log analysis, attack-signal contribution, captcha, WAF or paid plan. Coverage is limited and the supported bouncer does not provide a strict initial-sync/freshness gate; these limits must be reported honestly. External feed receipt and real decision enforcement are mandatory publication checks.
- Existing crash-consistent ZFS image snapshots are the recovery mechanism, not a newly promised off-site database backup. Preserve the volume and secret across rebuilds and rollback.
- Implementation approval authorizes local code and isolated verification only. Keep both repositories unpushed; activation, DNS changes and Netlify publication require separately authorized rollout and account access. If that access is unavailable, finish local verification and explicitly report publication/browser checks unperformed.
- Keep the repository's locked packages; if the lock changed before implementation, inspect the native module/tracker against this same contract and stop on a missing required capability rather than opening additional routes, allowing egress or using unsupported proxy internals.
